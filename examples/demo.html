第一篇：为什么用 slug 当文章 ID

2026-09-11 · 3 分钟

文章的标识要稳定且唯一。建议直接用 URL 里的 slug，例如 why-use-slug，这样换数据库、换后端都不影响已有的点赞记录。

第二篇：防重复点赞的三道防线

2026-09-11 · 5 分钟

前端禁用按钮只是第一道；第二道是服务端唯一索引；第三道是事务里的原子自增。三样凑齐，并发也不会把计数搞乱。

第三篇：这篇的计数器从 0 开始

2026-09-11 · 2 分钟

后端里没有记录的文章，接口返回 like_count: 0 而不是报错。所以新文章发出去，点赞数是 0 而不是空白或报错。

可以看到三篇是一次批量请求拿到的点赞数。点第一篇后再刷新页面，因为演示数据不落盘，它会回到初始值——真实环境里由数据库持久化。
