点赞系统 · 部署自检

逐条验证后端是否真的可用。检测会写入少量测试数据，文章 ID 以 check- 开头。

检测项 结论 实际情况
自检页测不到的三件事
  • 并发不丢数据 —— 本页是串行请求。并发要用命令行跑，见 tests/api-test.md 用例 9。
  • CORS 跨域 —— 本页与接口同源，浏览器不会发 Origin 头，测不了。 想确认的话在电脑上用命令行跑（把域名换成你的）：
    curl -s -i -H "Origin: https://evil.example.com" "https://你的域名/api/likes.php?article_id=test-001" | grep -i access-control
    没有任何输出 = 白名单生效（正确）； 输出里有 Access-Control-Allow-Origin: * 反而是错的。
  • 前端组件行为 —— 把点赞 HTML 插进博客模板后，实际点一下、刷新、看控制台有没有红色报错。 本页只验后端，不验你博客页面里的组件。

检测完记得把 check.html 从服务器删掉。 它会把接口信息暴露给任何访问者，虽然只能读点赞数、写测试数据，但没有留在服务器上的必要。

清理测试数据（在 phpMyAdmin 里执行）：

DELETE FROM like_records  WHERE article_id LIKE 'check-%';
DELETE FROM article_likes WHERE article_id LIKE 'check-%';
